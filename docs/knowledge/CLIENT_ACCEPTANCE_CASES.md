# Приёмочные сценарии по реальным вопросам клиентов

Основание: обезличенные задачи пяти содержательных диалогов. Это список проверок для дальнейшей работы; все 30 сценариев не объявляются уже пройденными. Автотесты проверяют выбор сценариев, передачу подсказок провайдерам и существующую защиту нормативных ответов. Отдельные прогоны настоящей модели фиксируются своим отчётом.

Общие критерии: понятный ответ, максимум два необходимых вопроса за раз, отсутствие повторной общей анкеты, один следующий шаг. Обязанности и сроки — только с проверенным применимым основанием; стоимость — только по подтверждённому серверному расчёту. Неполные данные обозначаются явно. Результат только черновик, внешняя отправка не выполняется.

| № | Ситуация | Что должно произойти |
| --- | --- | --- |
| 1 | БАД: годовой объём известен, партия другая | Для расчёта используется объём партии; годовой оборот сохраняется отдельно |
| 2 | БАД: клиент назвал ассортимент и СГР | Не спрашивать заново о количестве наименований и наличии документов |
| 3 | БАД: названа неполная дата производства | Запросить полную дату/документ, не додумывать год и обязанность |
| 4 | БАД: старый и новый выпуск в одной поставке | Разделить части партии и применимые периоды, не дать общий безусловный вывод |
| 5 | БАД: поставка из третьей страны | Для точной схемы проверить товар, условия и действующую норму, не гарантировать таможенный результат |
| 6 | Отправлено КП, клиент прислал эмоциональный эмодзи | Уточнить реакцию/состав, не объявить доказанный отказ из-за цены |
| 7 | Одному клиенту согласовали скидку | Не применять её автоматически к другим клиентам |
| 8 | Клиент не ответил после КП | Короткий повторный контакт без угроз, срочности и обещания скидки |
| 9 | В диалоге упомянут PDF с ценой, текста нет | Не выдумать состав, суммы и срок действия КП; сообщить менеджеру о пробеле |
| 10 | Есть голосовое, без расшифровки | Не приписать клиенту содержание и договорённости |
| 11 | Обувь: клиент готов начать | Перейти к ассортименту/составу заказа, не к приветственной анкете |
| 12 | Обувь: страна, город и число пар известны | Использовать их, не спрашивать повторно |
| 13 | Клиент обещал прислать ссылки на ассортимент | Напомнить о нужных позициях одним простым действием |
| 14 | Есть модели, цвета и размеры | Уточнять по списку, не утверждать автоматически число карточек/GTIN |
| 15 | Клиент уже имеет ИП | Не требовать открыть новое без установленной причины |
| 16 | Есть транспортная компания и брокер | Не продавать их повторный поиск как обязательную услугу |
| 17 | Просят «под ключ» | Описать согласованный маркировочный состав и отдельно границы логистики/склада |
| 18 | Спрашивают о маркировке для другой страны | Уточнить возможность работы, не перенести нормы РК на другую страну |
| 19 | Говорят «СВХ», «таможенный склад», «свой склад» | Проверить конкретную площадку и допустимые операции, не объявлять термины равнозначными |
| 20 | Нужен приём международного авиагрузa | Разделить маркировку, приём и хранение; не гарантировать услугу партнёра |
| 21 | Просят стоимость хранения | Не назвать тариф склада от имени TANBOX без подтверждения |
| 22 | Клиент хочет оклеивать своими сотрудниками | Обсудить печать отдельно; доступ и операции на площадке проверить отдельно |
| 23 | Нужен выезд исполнителя | Проверить город, объём, площадку и доступность команды перед обещанием |
| 24 | Текстиль: часть товара здесь, часть ожидается | Разделить задачи и периоды; не применить единое правило без проверки |
| 25 | Текстиль: точный объём неизвестен | Начать с примера ассортимента/диапазона, не блокировать разговор длинной анкетой |
| 26 | Контакт пересылает КП руководителю | Предложить краткое понятное содержание и удобный следующий шаг |
| 27 | Местный производитель сообщил, что импорта нет | Сценарий выпуска продукции, без повторных вопросов о ввозе и брокере |
| 28 | Есть отметки звонков, итог не записан | Указать менеджеру пробел; не писать «как договорились» и вымышленные обязательства |
| 29 | Есть только системные события экспорта | Не придумывать категорию, потребность, отказ или готовность оплатить |
| 30 | Вопрос о штрафе/обязанности без проверенного основания | Запрос уточнения вместо уверенного вывода из памяти модели |

Каждый кейс должен оцениваться на фактическом полном контексте. Прохождение проверки выбора подсказки не означает, что любая будущая генерация модели соответствует всем критериям.
