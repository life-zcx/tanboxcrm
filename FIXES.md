# Исправления TANBOX CRM

Дата: 10 ноября 2026 года. Исходный аудит: AUDIT_REPORT.md. Этот файл описывает текущую реализацию; прежний отчёт оставлен как историческая запись.

## Веб: самостоятельные страницы

| URL | Назначение |
| --- | --- |
| /login | Вход через одноразовый запрос браузера |
| /deals | Воронка, все этапы и загрузка дополнительных сделок |
| /clients | Клиенты, серверный поиск, фильтры и страницы |
| /clients/:id | Полная карточка клиента, история, AI, статусы и новая сделка |
| /ingest | Загрузка скриншотов и текста |
| /knowledge | База знаний и добавление правил |

Корень перенаправляет в воронку. При входе по прямой защищённой ссылке адрес сохраняется до авторизации. Карточка клиента является страницей с возвратом к исходному списку или воронке. Фильтры и номер страницы клиентов хранятся в URL. Поддерживаются перезагрузка, прямые ссылки, открытие в новой вкладке и история браузера. Неизвестный адрес показывает страницу «Не найдена».

Нестабильный путь IPv6 localhost исключён публикацией Docker на 127.0.0.1. Ссылка localhost переводит браузер на IPv4. Nginx отдельно выдаёт assets и возвращает 404 для отсутствующего файла; HTML не кешируется, хешированные ресурсы кешируются. DNS backend обновляется во время работы, чтобы пересоздание API не оставляло старый адрес upstream.

## Telegram: полноценная CRM

Главное меню через /start или /menu:

- Загрузить переписку: текст или пачка из 1–15 скриншотов, автоопределение клиента либо явная привязка к карточке.
- Клиенты: поиск по имени, телефону, БИН или компании, страницы, карточка и последняя переписка.
- Что ответить: история клиента, деловой/дружелюбный/экспертный тон, дожим либо собственный запрос.
- Воронка: количество и суммы по этапам.
- База знаний: тарифы и активные правила.
- Вход в веб: отдельное действие, не заменяющее функции CRM.
- Помощь и отмена действия.

В карточке доступны добавление переписки, смена статуса с обновлением сделки, ответ ИИ и WhatsApp. После импорта показываются понятные действия. Для обычного текста без выбранного режима бот уточняет, нужно ли сохранить переписку или задать вопрос по клиенту: случайное сообщение не становится карточкой.

Пачка резервируется до первого await, ограничена по числу/объёму файлов и хранит выбранного клиента на момент начала. Неудачные текст и скриншоты можно повторить кнопкой. Новая пачка во время обработки не принимается молча: пользователь получает объяснение. Сообщения отправляются как обычный текст, поэтому Markdown в именах и AI-ответах не ломает Telegram.

## Провайдер ИИ

По реальному ответу Google прежний gemini-2.5-flash-lite больше недоступен новым пользователям, а alias отвечал 503. Настроены и проверены реальным запросом gemini-3.5-flash-lite и резервная gemini-3.1-flash-lite. Пробный текст успешно распознан как заказ на 100 пар обуви. Gemini получает явную схему JSON; локальная проверка результата остаётся обязательной. Поддерживается нормализация списка возражений в строку.

Встроенные лимиты/квоты и внешняя доступность Google/OpenAI не контролируются приложением. При 429 соблюдается пауза для конкретной модели; пробуется максимум одна явно настроенная альтернативная модель. Приложение не подменяет распознавание шаблонной карточкой.

## Удаление клиента и хронология нескольких скриншотов

В веб-карточку и Telegram добавлено полное удаление с подтверждением. Записи клиента, сделки, сообщения и AI-рекомендации удаляются каскадно в транзакции вместе с постановкой файлов в устойчивую очередь. Скриншоты без других владельцев удаляются с диска; общие изображения остаются до удаления последней карточки. Ошибки файловой системы приводят к HTTP 202 и повторной очистке, а просмотр файла после удаления последней ссылки сразу запрещён. Повторный запрос удаления корректно сообщает о ещё не завершённой очистке. Резервные копии не изменяются.

Причина перемешивания: сообщения одной пачки получали одинаковый createdAt, а чтение дополнительно сортировало их по случайному UUID. Добавлены position и originalTime; все API, контекст ИИ и Telegram используют сохранённую последовательность. Миграция восстанавливает старый порядок из extractedInfo.messages, проверяя некорректный JSON без падения. Она не исправляет прежние ошибки распознавания, отсутствующие в исходном сохранённом массиве.

Gemini возвращает отдельный массив сообщений для каждого пронумерованного изображения. Сервер проверяет полноту пачки, объединяет изображения по выбранному порядку и убирает совпадающие последовательности на границах. Глобальной сортировки по времени без даты нет: она ломала бы переход через полночь. В веб-загрузчике добавлены стрелки изменения порядка, в Telegram альбом упорядочивается по message_id до обработки.

Проверены каскадное и повторное удаление, сбой удаления файла и повтор очереди, общие скриншоты, одинаковое время импорта, пагинация, Telegram-подтверждение и порядок альбома. На отдельной legacy-БД миграция восстановила исходную последовательность при обратных UUID и выдержала повреждённый JSON. Реальный Gemini на двух синтетических скриншотах с пересечением сохранил четыре сообщения в порядке 23:58, 23:59, 00:01, 00:02. Перед применением создана резервная копия backups/crm-20261110-010635.

## Серверный расчёт стоимости, 11.11.2026

Миграция 202611110006 добавила CommercialQuote с каскадом клиента и commercialEvidence у AISuggestion. В карточке появился раздел «Расчёт стоимости»: пакет, конкретная партия, карточки, сопровождение, SSCC, макет, доставка, срочность и явная скидка с причиной. Сумма не принимается от браузера: вычисляется на сервере по проверенному публичному API TANBOX. Версии сохраняют входные параметры, ставки, хеш и источник; отзыв не удаляет историю и не оживляет старый вариант автоматически. Годовой объём не подставляется в партию. Заголовок карточки также больше не объявляет произвольный оценочный объём партией.

Прайс проверяется по строгой схеме, кеш обновляется через пять минут; при сбое допускается проверенный снимок не старше суток. Изменившийся прайс, отзыв, истечение внутреннего срока или нарушение целостности исключают расчёт из подсказок. Минимум PRO применяется отдельно, SSCC в PRO не начисляется повторно, макеты взаимоисключающие, срочность не увеличивает карточки/сопровождение/доставку. Коды оператора, склад, брокер и индивидуальное оборудование не считаются включёнными.

Помощник веба и Telegram получает пригодный расчёт этого клиента; основания сохраняются вместе с ответом. В Telegram добавлен просмотр расчёта из карточки. Явные денежные суммы ответа проверяются по расчёту до сохранения. При ответе с денежной суммой условия внешних расходов добавляются программно: живая проверка выявила, что модель могла забывать их. Проверка чисел не заменяет проверку менеджером всех смысловых формулировок.

Пройдены 57 серверных тестов, включая арифметику реального КП 883 900 → 750 000 ₸, границы, скидки, принадлежность клиенту, устаревание, смену прайса, отзыв и блокировку неподтверждённых сумм. Изолированный dump/restore сравнивает весь расчёт и коммерческие основания ответов. Новый браузерный тест проверяет поля, выбор версии, копирование с условиями, отзыв и доступность истории при сбое прайса. Резервная копия перед обновлением: backups/crm-20261111-003709; она восстановлена в отдельной БД и мигрирована до новой схемы без расхождений байтов и текстов знаний. Restore-скрипт теперь явно запускает миграции перед стартом приложения после старого backup.
